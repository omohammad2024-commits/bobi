# بابی

یک ربات ایجنت همه‌کاره برای تلگرام. بابی فقط چت نمی‌کند: خودش تصمیم می‌گیرد چه ابزاری را صدا بزند، نتیجه را می‌خواند، و بعد جواب می‌دهد.

```
کاربر ──▶ مدل ──▶ [ابزار] ──▶ مدل ──▶ جواب
              ▲                  │
              └──────────────────┘
```

---

## شروع سریع

```bash
bun install
cp .env.example .env
```

سپس در `.env` دو مقدار الزامی را پر کن:

| متغیر | توضیح |
|---|---|
| `TELEGRAM_BOT_TOKEN` | از [@BotFather](https://t.me/BotFather) |
| `OWNER_TELEGRAM_ID` | شناسهٔ عددی خودت، از [@userinfobot](https://t.me/userinfobot) |

```bash
bun run dev
```

ربات با همان تنظیمات بالا کار می‌کند، ولی **بدون مدل واقعی** فقط پاسخ آزمایشی می‌دهد. برای وصل کردن مدل:

1. یک کلید رمزنگاری بساز: `openssl rand -hex 32` و در `BOBI_AI_KEY_MASTER_KEY` بگذار.
2. در تلگرام `/ai` را بفرست.
3. پروایدر اضافه کن (آدرس + کلید API)، مدل اضافه کن، و فعالش کن.

بدون `BOBI_AI_KEY_MASTER_KEY` نوشتن اعتبارنامه **رد می‌شود** — هیچ کلیدی به‌صورت متن ساده ذخیره نمی‌شود.

## چه کاری می‌کند

| ابزار | کار |
|---|---|
| `calculator` | جمع، تفریق، ضرب، تقسیم — بدون `eval` |
| `date_time` | تاریخ و ساعت در هر timezone، با پشتیبانی DST |
| `text_utilities` | آمار متن: کاراکتر، کلمه، جمله، خط |
| `unit_converter` | طول، جرم، حجم، دما |
| `fetch_url` | خواندن یک صفحهٔ وب و تبدیلش به متن |
| `web_search` | جستجوی وب (DuckDuckGo بدون کلید، یا Tavily با کلید) |
| `remember` / `recall` / `forget` | حافظهٔ بلندمدت، مجزا برای هر کاربر |
| `remind_at` / `list_reminders` / `cancel_reminder` | یادآور زمان‌دار |
| `mcp_<server>` | هر ابزاری که یک سرور MCP ارائه می‌دهد |

### پیوست‌ها

عکس، پیام صوتی و سند را مستقیم در چت بفرست — بابی خودش برمی‌دارد:

| می‌فرستی | چه می‌شود |
|---|---|
| عکس | بزرگ‌ترین سایز (نه thumbnail) به مدل می‌رود |
| پیام صوتی | به مدل می‌رود (Gemini صدا را مستقیم می‌فهمد) |
| PDF | به‌عنوان سند به مدل می‌رود |

**پیوست در تاریخچه ذخیره نمی‌شود** — فقط یک نشانه (`[۱ پیوست]`). چون base64 در
دیتابیس آن را بی‌مرز بزرگ می‌کند، و مدل نیازی ندارد عکس دیروز را در هر پیام
بعدی دوباره ببیند.

پیوستی که قابل استفاده نباشد **بی‌صدا گم نمی‌شود** — به کاربر گفته می‌شود چرا
(حجم زیاد یا نوع پشتیبانی‌نشده). عکس گم‌شده بدتر از خطاست: مدل با اطمینان دربارهٔ
چیزی حرف می‌زند که هرگز ندیده.

## اتصال ابزارهای بیرونی با MCP

[MCP](https://modelcontextprotocol.io) یک استاندارد باز است: هر سروری که آن را
حرف بزند، ابزارهایش را با خودش می‌آورد. با یک انتگریشن، بابی به کل اکوسیستم
وصل می‌شود — بدون نوشتن تک‌تک ابزارها.

فایل `mcp.json` کنار ربات بساز:

```json
{
  "servers": {
    "files": {
      "transport": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/dir"],
      "enabled": true
    },
    "remote": {
      "transport": "http",
      "url": "https://mcp.example.com/mcp",
      "token": "…",
      "enabled": false
    }
  }
}
```

هر سرور متصل، یک ابزار `mcp_<name>` می‌شود. مدل نام ابزار واقعی را در فیلد
`tool` و آرگومان‌ها را در `arguments` می‌دهد.

### امنیت MCP

**یک سرور stdio یک دستور پوسته است** که با اختیارات کامل پروسهٔ ربات اجرا
می‌شود. بنابراین:

- فقط **مالک** سرور تعریف می‌کند — نه مدل، نه کاربر عادی.
- هر سرور تا وقتی `"enabled": true` نگوید **اجرا نمی‌شود**. کپی‌کردن یک فایل
  config هیچ‌چیز را اجرا نمی‌کند.
- فیلدهای ناشناخته **رد** می‌شوند، نه نادیده — تا یک غلط تایپی به یک اجرای
  ناخواسته تبدیل نشود.
- مدل فقط ابزاری را می‌تواند صدا بزند که سرور **خودش اعلام کرده باشد**.
- هر خطا در استارتاپ لاگ می‌شود؛ یک سرور خراب بقیه را از کار نمی‌اندازد.

## امنیت

این بخش مهم‌ترین قسمت پروژه است. هر مورد زیر با تست پوشش داده شده.

### ۱. دسترسی کاربر

هر کسی که در چت خصوصی به ربات پیام بدهد ابتدا `pending` می‌شود و **هیچ پاسخی از مدل نمی‌گیرد**. مالک در `/admin → دسترسی کاربران` تأیید یا رد می‌کند. بدون این، هر غریبه‌ای می‌توانست بودجهٔ API تو را خرج کند.

گروه‌ها گردش تأیید جداگانهٔ خودشان را دارند.

### ۲. ابزارها فقط از یک مسیر اجرا می‌شوند

مدل فقط *نام* ابزار را انتخاب می‌کند. مجوز از سرور می‌آید:

- **`ToolActor`** از `ctx.from.id` ساخته می‌شود — هرگز از متن پیام یا خروجی مدل.
- **`ToolExecutor`** تنها مسیر اجراست: بررسی مجوز قبل از بررسی فعال‌بودن، اعتبارسنجی ورودی قبل از اجرا، تایم‌اوت، و سقف هم‌زمانی.
- ابزاری که مدل «اختراع» کند `not_found` می‌گیرد؛ ابزاری که مجوزش را ندارد `not_allowed` — و این به مدل برگردانده می‌شود تا بتواند مسیرش را عوض کند.

### ۳. خروجی ابزار «داده» است، نه «دستور»

هر نتیجه داخل `<tool_result>` پیچیده می‌شود و system prompt صراحتاً می‌گوید محتوای آن دستور نیست. یک صفحهٔ وب مخرب نمی‌تواند به ایجنت بگوید قوانینش را نادیده بگیرد.

### ۴. SSRF

`fetch_url` و جستجو از همان ترانسپورت AI استفاده می‌کنند:

- **`validateTarget`** — scheme، userinfo، و میزبان‌های خصوصی
- **`resolveTarget`** — DNS را resolve می‌کند و **هر** آدرس برگشتی را بررسی می‌کند (دفاع در برابر DNS rebinding)
- **`pinnedFetch`** — سوکت را به آدرس تأییدشده می‌بندد، ریدایرکت را دنبال نمی‌کند، و حجم پاسخ را محدود می‌کند

ریدایرکت‌ها دستی و محدود دنبال می‌شوند، چون هر hop باید دوباره اعتبارسنجی شود — یک URL عمومی که به `169.254.169.254` ریدایرکت کند در غیر این صورت یک SSRF کامل است.

### ۵. بودجه

یک پیام کاربر می‌تواند چندین فراخوانی مدل و ابزار بشود، پس هر چیز سقف دارد:

| سقف | پیش‌فرض | متغیر |
|---|---|---|
| رفت‌وبرگشت مدل | ۶ | `BOBI_AGENT_MAX_ITERATIONS` |
| فراخوانی ابزار در هر پیام | ۱۲ | `BOBI_AGENT_MAX_TOOL_CALLS` |
| زمان کل یک اجرا | ۱۲۰s | `BOBI_AGENT_TOTAL_TIMEOUT_MS` |
| پیام در دقیقه (هر کاربر) | ۲۰ | `BOBI_RATE_LIMIT_PER_MINUTE` |
| ابزار در ساعت (هر کاربر) | ۲۰۰ | `BOBI_RATE_LIMIT_TOOL_CALLS_PER_HOUR` |

وقتی سقفی پر شود، یک فراخوانی نهایی **بدون ابزار** انجام می‌شود تا کاربر با هر چیزی که جمع شده جواب بگیرد، نه اینکه معلق بماند.

### ۶. لاگ

خروجی JSON ساختاریافته در سطح `BOBI_LOG_LEVEL`. یک redactor الگوهای اعتبارنامه (توکن تلگرام، `sk-…`، `tvly-…`، `Bearer …`) و فیلدهای حساس را حذف می‌کند — حتی اگر کدی اشتباهاً سکرتی را پاس بدهد.

## معماری

```
src/
├── index.ts              نقطهٔ شروع: سیم‌کشی همه‌چیز
├── agent/                ← قلب ایجنت
│   ├── loop.ts           حلقهٔ مدل → ابزار → مدل، با بودجه‌ها
│   ├── prompt.ts         ساخت system prompt از فکت‌های سرور
│   └── transcript.ts     واژگان یک اجرا (step، نتیجه، wrap)
├── conversation/
│   ├── engine.ts         یک turn = یک اجرای کامل ایجنت
│   └── summary.ts        خلاصه‌سازی تاریخچهٔ قدیمی
├── ai/                   لایهٔ سرویس‌ها
│   ├── provider.ts       قرارداد neutral (شامل tool calling)
│   ├── gateway.ts        انتخاب پروایدر/مدل + failover
│   ├── {openai_compatible,anthropic,gemini}.ts
│   ├── dns_guard.ts      اعتبارسنجی آدرس
│   ├── pinned_transport.ts  سوکت مقید به آدرس تأییدشده
│   └── secret_store.ts   AES-256-GCM
├── tools/                ابزارها — همه از یک قرارداد
│   ├── types.ts          Tool<TIn, TOut>
│   ├── executor.ts       تنها مسیر اجرا
│   ├── registry.ts       فهرست
│   ├── validate.ts       اعتبارسنجی ورودی
│   └── {calculator,date_time,...}.ts
├── auth/                 هویت و مجوز
├── groups/               تأیید گروه + پنل مالک
├── search/               پروایدرهای جستجو
├── scheduler/            یادآورها
├── storage/              SQLite — تنها جایی که SQL هست
├── core/                 logger، rate limit، usage، deadline
└── config/               خواندن env با پیش‌فرض‌های امن
```

### اصول طراحی

1. **یک قرارداد برای همه‌چیز.** ابزار جدید = یک فایل که `Tool` را پیاده می‌کند.
2. **مرزها صریح‌اند.** موتور grammY نمی‌شناسد؛ ابزارها storage نمی‌شناسند؛ آداپترها فقط wire format می‌دانند.
3. **همه‌چیز قابل تست است.** ساعت تزریق می‌شود، شبکه stub می‌شود، تصمیم‌ها توابع خالص‌اند.
4. **شکست بسته.** خطای storage ≠ تأیید. کلید ناموجود ≠ ادامه با متن ساده.

## افزودن یک ابزار

یک فایل بساز و در `DEFAULT_TOOLS` ثبتش کن. همین.

```ts
// src/tools/word_count.ts
import { ToolError } from "./errors";
import type { Tool, ToolContext } from "./types";

export const wordCountTool: Tool<{ text: string }, { words: number }> = {
  name: "word_count",
  description: "تعداد کلمات یک متن را می‌شمارد.",
  enabled: true,
  permission: { requires: ["tools:word_count"] },
  input: {
    fields: {
      text: { type: "string", required: true, maxLength: 10_000 },
    },
  },
  async run(input, _ctx) {
    const words = input.text.trim().split(/\s+/).filter(Boolean).length;
    if (words === 0) throw new ToolError("invalid_input", "متن خالی است.");
    return { words };
  },
};
```

```ts
// src/tools/service.ts
export const DEFAULT_TOOLS = [
  // ...
  wordCountTool,
];
```

همین کافی است: اعتبارسنجی، مجوز، تایم‌اوت، و تعریف JSON Schema برای مدل **خودکار** اعمال می‌شوند.

**قواعد:**
- در `run` فقط `ToolError` پرتاب کن — نه خطای خام OS یا شبکه.
- ورودی را قبل از استفاده بررسی کن؛ tool body فرض می‌کند ورودی معتبر است، ولی دفاع عمقی ارزان است.
- هیچ‌وقت متن پیام یا سکرت را لاگ نکن.

## محدودیت‌ها

صادقانه:

- **آداپترها روی endpoint واقعی تست نشده‌اند.** پارس با fixture تست می‌شود، ولی صحت زنده نیاز به کلید واقعی دارد.
- **پارسر DuckDuckGo به HTML عمومی تکیه دارد.** ممکن است یک روز بشکند؛ در آن صورت تست با پیام واضح شکست می‌خورد، نه خرابی خاموش.
- **یادآورها در پروسه اجرا می‌شوند.** اگر ربات خاموش باشد یادآور نمی‌رسد — ولی در استارتاپ بعدی یادآورهای عقب‌افتاده (تا یک ساعت) می‌رسند.
- **هزینهٔ نمایش‌داده‌شده تخمینی است.** جدول قیمت نشانگر است، نه صورت‌حساب.
- **rate limit در حافظه است.** ری‌استارت آن را پاک می‌کند.
