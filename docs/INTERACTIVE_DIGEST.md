# خلاصهٔ تعاملی (`/digest`)

> فاز ۲، آیتم ۳ — محصولی‌سازی دایجست صبحگاهی (تمایز فراتر از هرمس).

دایجست تا پیش از این فقط یک **متن** بود که ساعت ۸:۰۰ صبح از طریق
`/blueprint run morning_digest` زمان‌بندی می‌شد. حالا با دستور **`/digest`**
(فقط مالک) همان دایجست **در لحظه** و **تعاملی** ساخته می‌شود: هر آیتم دکمه‌های
لمسی خودش را دارد، هر لمس بلافاصله اعمال می‌شود و پیام **درجا ویرایش**
می‌شود — پیام تازه تلنبار نمی‌شود.

## چه می‌بینی

```
/digest
```

پیام شامل همان بخش‌های دایجست متنی است (تاریخ، کارهای امروز، یادآورها،
پیشنهادهای حافظه، مصرف ۲۴ ساعت اخیر، سرخط خبرها، تازه‌ترین حافظه‌ها) با این
دکمه‌ها:

| بخش | دکمه‌ها | اثر |
|---|---|---|
| کار زمان‌بندی‌شده | «▶️ شروع» | اجرای **یک‌بارهٔ** اکشن همان کار، همین حالا (زمان‌بندی دست نمی‌خورد) |
| | «🗑 حذف» | تأیید دومرحله‌ای، بعد حذف کار |
| یادآور | «✅ انجام شد» | لغو یادآور (انجام شد) |
| پیشنهادهای حافظه | «🧠 بررسی پیشنهادها» | باز کردن نمای بررسی: هر پیشنهاد «✅ تأیید» / «❌ رد» |
| حافظه | «📖 جزئیات» | ارسال متن کامل همان حافظه (پیام جداگانه) |
| — | «🔄 به‌روزرسانی» | بازسازی دایجست و ویرایش درجا |

حالت‌های خالی، خالیِ «خراب» نیستند: «امروز کار زمان‌بندی‌شده‌ای نداری؛ روز
آرومی پیش روئه.» و «پیشنهاد در انتظاری نداری 🎉».

## دوزبانه

متن دایجست **و** همهٔ دکمه‌ها از `Lang` مالک (`/lang`) پیروی می‌کنند. موتور
سازنده (`src/digest/builder.ts`) حالا دادهٔ بخش‌ها را زبان‌خنثی می‌سازد
(`buildDigestData`) و رندر را per-language انجام می‌دهد (`renderDigestSection`
با `fa`/`en`). API فارسی قدیمی (`buildDigest`/`formatDigest`) بایت‌به‌بایت
حفظ شده — دایجست متنی زمان‌بندی‌شده و تست‌هایش دست‌نخورده‌اند.

نکته: خلاصهٔ پیشنهادهای نگهدارنده در دیتابیس فقط فارسی ذخیره می‌شود
(`summary_fa`)؛ در نمای بررسی همان متنِ ذخیره‌شده نمایش داده می‌شود.

## «شروع» دقیقاً چه می‌کند

«▶️ شروع» اکشن ذخیره‌شدهٔ کار را **یک بار اضافه** اجرا می‌کند؛ `nextRunAtMs`
و زمان‌بندی بعدی عوض نمی‌شود (رقابتی با اسکجولر نیست):

- اکشن `tool`: اجرای ابزار با اکتورِ مالکِ ساخته‌شده در سرور (همان مسیر
  `authorizeToolUse` در `cmd_auto`)؛
- اکشن `message` / `agent`: ارسال **فقط** به همان چتی که لمس از آن آمده.
  کاری که به چت دیگری اشاره کند، با پیام صادقانه رد می‌شود
  («اجرای مستقیم فقط برای چت خودت ممکنه») — هیچ لمسی باعث ارسال
  cross-chat نمی‌شود.

تأیید/رد پیشنهادها از همان ابزار `curator_decide` می‌گذرد (نه کپیِ منطق):
انقضا، یک‌طرفه‌بودن وضعیت و «اول اعمال، بعد ثبت» دقیقاً مثل مسیر ابزار
اعمال می‌شود.

## زمان‌بندی ۸:۰۰ چه شد

**بدون تغییر.** تحویل زمان‌بندی‌شده همان نسخهٔ متنی (`build_digest`) را
می‌فرستد — ساعت ۸ صبح دکمه لازم نیست. `/digest` نسخهٔ تعاملیِ درخواستی است؛
هر وقت خواستی همان دایجست را با دکمه‌ها ببین.

## بررسی سطح حمله

- **جعل کالبک:** `parseDigestCallback` سخت‌گیرانه است (آی‌دی عددی ۱ تا ۱۰
  رقم، ایندکس حافظه تک‌رقمی، شناسهٔ پیشنهاد دقیقاً `cur-` + ۱۶ hex)؛ هر چیز
  دیگری بی‌اثر مصرف می‌شود. هیچ متن کاربری وارد `callback_data` نمی‌شود —
  فقط آی‌دی‌های ساخته‌شده در سرور.
- **لمس غیرمالک:** گیت سطح دسترسی هم در روتر (`requireOwnerTier`) و هم در
  هندلر (`isOwnerCtx`) روی هر لمس دوباره چک می‌شود؛ همهٔ خواندن/نوشتن‌ها با
  آی‌دی لمس‌کننده scope می‌شوند. پنهان‌بودن دکمه مرز امنیتی نیست.
- **محتوای کاربر در دایجست:** پیام‌ها **plain text** (بدون `parse_mode`)
  ارسال می‌شوند؛ کاراکترهای markdown/کنترلیِ داخل نام کار، متن یادآور یا
  حافظه نمی‌توانند پیام را بشکنند یا دکمهٔ جعلی تزریق کنند. فاصله‌ها جمع
  (`oneLine`) و هر آیتم clip می‌شود.
- **URL تیترها:** فقط hostname نمایش داده می‌شود؛ query string (توکن،
  session id) هرگز به چت نمی‌رسد.
- **حذف کار** دومرحله‌ای است (آماده‌سازی ← تأیید ← حذف).

## چیزهایی که عمداً بیرون ماند

- **Snooze یادآور** («بعداً یادم بنداز»): در این نسخه نیست؛ «انجام شد»
  یادآور را می‌بندد. اگر خواستی، آیتم بعدی همین‌جاست.
- **اجرای مستقیم کارِ چتِ دیگر:** عمداً محدود به چتِ لمس است (بالا).
- **مدیای خروجی ابزار در «شروع»:** فقط چانک‌های متنی تحویل می‌شود.
- **نمای بررسی بیش از ۱۰ پیشنهاد:** ۱۰ تای اول با دکمه، بقیه شمارش
  می‌شوند («…و N پیشنهاد دیگر — فهرست کامل با /curator»).

## فایل‌ها

- `src/digest/builder.ts` — هستهٔ دوزبانه (دادهٔ زبان‌خنثی + رندر per-lang؛
  API فارسی قدیمی حفظ شده)
- `src/digest/interactive.ts` — پروتکل `dgst:`، پارس سخت‌گیرانه، رندر
  متن+کیبورد، نمای بررسی پیشنهادها، کارت حافظه (خالص، تست‌پذیر)
- `src/bot/digest_cmd.ts` — ثبت `/digest`، هندلر کالبک‌ها، جهش‌های state،
  `runTaskNow`، تصمیم نگهدارنده از طریق ابزار `curator_decide`
- `src/bot/bot.ts` — ورودی `COMMAND_HELP`، شاخهٔ روتر `dgst:`
- `src/bot/menu.ts` — ورودی منوی مالک (`BUILTIN_COMMAND_DEFS`)
- `src/bot/palette.ts` — اجرای لمسی `/digest` از مرورگر دستورها
- `src/index.ts` — تزریق resolver تیترها به دایجست تعاملی
- `tests/interactive_digest.test.ts` — ۳۰ تست: پروتکل، رندر دوزبانه،
  جهش‌ها، جعل، برش پیام بلند
