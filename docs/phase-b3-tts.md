# فاز B3 — پاسخ صوتی (TTS Voice Replies)

کاربر با دستور `/voice` حالت صوتی را برای خودش روشن/خاموش می‌کند؛ وقتی
روشن باشد، پاسخ موتور به‌جای متن، به‌صورت پیام صوتی (voice) تلگرام ارسال
می‌شود.

قرارداد در تست‌های `tests/audio_tts.test.ts` پین شده است؛ هر تغییر عمدی
در این رفتار باید اول در همان تست‌ها نوشته شود.

## رفتار

| وضعیت | رفتار |
|---|---|
| `/voice` با TTS پیکربندی‌شده | `voice_mode` کاربر بین `1`/`0` تاگل می‌شود + تأیید فارسی |
| `/voice` بدون TTS (`TTS_BASE_URL` خالی) | پیام «پیکربندی نشده»؛ **pref ست نمی‌شود** (فلگ روشن بدون endpoint بی‌معنی است) |
| `voice_mode=1` و TTS فعال | هر چانک پاسخ سنتز و با `replyWithVoice` ارسال می‌شود — به‌جای متن |
| هر خطای TTS در نوبت | کل پاسخ به‌صورت متن ارسال می‌شود + یک یادداشت فارسی که تبدیل به صدا ناموفق بود |
| پاسخ بلندتر از سقف صوتی | اولِ پاسخ صوتی، بقیه متن + یک یادداشت — هیچ محتوایی گم نمی‌شود |
| `voice_mode=0` یا TTS غیرفعال | رفتار قبلی: فقط متن |

## راه‌اندازی

در `.env` (پیشوندها را از `.env.example` ببینید):

```
TTS_BASE_URL=https://api.openai.com/v1
TTS_API_KEY=<کلید>
TTS_MODEL=tts-1
TTS_VOICE=alloy
```

- `TTS_BASE_URL` خالی = غیرفعال؛ `/voice` در این حالت فقط اطلاع می‌دهد.
- هر endpoint سازگار با `/audio/speech` (بدنه‌ی `{model, input, voice,
  response_format}`) کار می‌کند. فرمت درخواستی `"opus"` است (ogg/opus —
  همان چیزی که تلگرام به‌عنوان voice می‌پذیرد)؛ media type از هدر پاسخ
  خوانده می‌شود و در نبود آن `audio/ogg` فرض می‌شود.
- pref در جدول `user_prefs` (`user_id`, `key`, `value`) ذخیره می‌شود؛ کلید
  فعلی `voice_mode` است. `Storage.getUserPref/setUserPref` تنها API این
  جدول است.

## سقف‌ها (caps)

- **هر فراخوانی سنتز:** حداکثر ۴۰۰۰ کاراکتر (`MAX_TTS_CHARS`). بیشتر از آن
  **رد** می‌شود (خطای `invalid_response`) — کوتاه‌سازی بی‌صدا یعنی کلماتی
  که کاربر هرگز نمی‌شنود. تکه‌تکه کردن با caller است (`splitForSpeech`).
- **هر پاسخ:** حداکثر ۲ چانک اول و در مجموع ۸۰۰۰ کاراکتر صوتی می‌شود
  (`MAX_VOICE_CHUNKS` / `MAX_VOICE_CHARS`)؛ مازاد به‌صورت متن می‌آید.
- **هر درخواست TTS:** تایم‌اوت ۹۰ ثانیه (`TTS_TIMEOUT_MS`).
- پاسخ باینری تا سقف ۸MB (`MAX_RESPONSE_BYTES` در ترنسپورت) خوانده می‌شود.

## مدل امنیتی

- **مسیر SSRF-hardened:** مثل B2 — `resolveTarget` + `pinnedFetch`؛ بدون
  دنبال‌کردن ریدایرکت؛ هاست لوکال/پرایوت بدون opt-in مالک رد می‌شود.
- **بایت‌های صوتی** فقط به endpoint پیکربندی‌شده می‌روند، روی دیسک نوشته
  نمی‌شوند، لاگ نمی‌شوند و در تاریخچه ذخیره نمی‌شوند — بعد از ارسال به
  کاربر رها می‌شوند. (ورودی TTS خروجیِ خودِ مدل است، نه صدای کاربر، ولی
  همان قانون اعمال می‌شود.)
- **خطاها** فقط `AiError` دسته‌بندی‌شده؛ بدنه‌ی خام هرگز به خطا یا پیام
  کاربر راه پیدا نمی‌کند.
- باینری پاسخ از `rawBody` ترنسپورت خوانده می‌شود، نه از رشته‌ی UTF-8 —
  دیکد متنی بایت‌های ogg را خراب می‌کرد.
- `/voice` با همان گیت کاربرِ مسیر پیام (تأییدشده/مالک) محافظت می‌شود؛
  خواندن pref اگر خطا بدهد، پاسخ به‌صورت متن ارسال می‌شود (fail به متن،
  نه به سکوت).
