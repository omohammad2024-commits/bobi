# اشتراک‌گذاری مهارت بین نمونه‌ها (فاز ۴، آیتم ۵)

> یک مهارت را از یک بابی صادر کن، به بابیِ دیگر بده، همان‌جا وارد کن — بدون مارکت‌پلیس عمومی، بدون امضای دیجیتال؛ مرز اعتماد = کارت بررسی + غیرفعالِ پیش‌فرض + همان خط لولهٔ اعتبارسنجی فاز ۳.

## دستورها (فقط مالک)

| دستور | اثر |
|---|---|
| `/skill export <نام>` | صدور بستهٔ قابل انتقال مهارت؛ فایل `.bobiskill` را به‌صورت document برمی‌گرداند |
| `/skill import <نشانی>` | دریافت بسته از نشانی (همان محافظ SSRF فاز ۳)، اعتبارسنجی، کارت بررسی |
| ارسال فایل `.bobiskill` با کپشن «/skill import» | وارد کردن از فایل ارسالی (سقف حجم قبل و بعد از دانلود) |
| ریپلایِ «/skill import» به پیام حاوی فایل `.bobiskill` | همان |
| ریپلایِ «/skill import» به پیام حاوی متن بسته | وارد کردن از متن پیست‌شده |

## قالب بسته (`.bobiskill`)

یک فایل JSON تک‌تکه، خوانا و قابل بازبینی — بدون باینری:

```jsonc
{
  "format": "bobi-skill-package",
  "formatVersion": 1,
  "skill": {
    "name": "memory-coach",
    "version": "1.2.0",            // اختیاری
    "description": "…",
    "triggers": ["memory"],
    "skillFile": "---\nname: memory-coach\n… (بایت‌به‌بایت همان فایل نصب‌شده)"
  },
  "metadata": {
    "exportedAt": "2026-10-19T…",
    "sourceInstance": "hostname",
    "capabilities": ["prompt-context"]
  },
  "checksum": "sha256 hex روی فرم کانونیکال (بدون خود فیلد checksum)"
}
```

- `skillFile` دقیقاً بایت‌های فایل نصب‌شده است؛ هنگام وارد کردن، همان پارسر لودر روی همین بایت‌ها اجرا می‌شود.
- `capabilities` صرفاً اعلامی است: همیشه `prompt-context` (بدنه وارد system prompt می‌شود)، به‌علاوهٔ `external-links` اگر بدنه URL داشته باشد و `flagged:<kind>` برای هشدارهایی که اسکنِ لحظهٔ صدور پیدا کرده. **مهارت‌ها هیچ دسترسی/مجوزی نمی‌دهند و هیچ کدی اجرا نمی‌کنند** — این فیلد فقط برای بازبینی است و هنگام وارد کردن اسکن از نو انجام می‌شود.
- سقف حجم بسته = همان `SKILLS_MAX_FILE_BYTES` (۶۴KB) در همهٔ مسیرهای ورودی. عملاً مهارت‌های نزدیک به سقف، بسته‌ای بزرگ‌تر از سقف تولید می‌کنند و از مسیر چت قابل وارد کردن نیستند (محدودیت مستند، نه باگ).

## نسخه (`version:`)

فیلد اختیاری frontmatter (آزاد، عرفاً semver مثل `1.2.0`)؛ برچسب نامعتبر بی‌سروصدا نادیده گرفته می‌شود، هرگز خطا نمی‌دهد. هنگام وارد کردن:

| وضعیت | رفتار |
|---|---|
| مهارت تازه (هم‌نامی نصب نیست) | کارت بررسی عادی |
| نسخهٔ بسته جدیدتر | کارت بررسی با «⬆️ ارتقا: 1.2.0 ← 1.3.0» |
| نسخهٔ بسته قدیمی‌تر | کارت بررسی با **هشدار صریح دانگرید** («⚠️ … قدیمی‌تر است!») — تصمیم با مالک |
| نسخه یکسان | یادداشت «همان نسخه دوباره نصب می‌شود» |
| یک طرف نسخه ندارد | «نسخه مشخص نیست؛ مثل نصب تازه بررسی کن» |

مقایسه عددیِ بخش‌بخش است (`1.10.0 > 1.9.0`)؛ برچسبِ گم/نامعتبر = `0.0.0`.

## جریان وارد کردن (قدم‌به‌قدم)

1. **بسته‌خوانی** (`src/skills/share.ts` → `verifySkillPackage`): سقف حجم، JSON بودن، نشانگر فرمت، نسخهٔ فرمت، کامل بودن بخش‌ها، بازسازی checksum و مقایسه. هر دست‌کاریِ پس از صدور (بدنه، نسخه، متادیتا) = رد با پیام روشن «بسته دست‌کاری شده است».
2. **اعتبارسنجی** (`planSkillImport` → همان `prepareSkillInstall` فاز ۳): سقف حجم، پارس frontmatter، نام kebab-case، سقف تعداد — به‌علاوهٔ اسکن تزریق پرامپت (`scanSkillBody`) که هشدارهایش روی کارت می‌آید. نسخه، تداخل نام را به «جایگزینی» تبدیل می‌کند.
3. **کارت بررسی وارداتی**: بلوک اعتماد (🔒 تأیید یکپارچگی، وضعیت نسخه، منبع، زمان/نمونهٔ صدور، قابلیت‌های اعلامی، ⏸️ یادداشت «غیرفعال نصب می‌شود») + کارت بررسی استاندارد مهارت (نام، توضیح، تریگرها، حجم، هشدارها، ۲۰ خط اول).
4. **تأیید** (`approvePendingImport`): توکن یک‌بارمصرفِ ۱۰دقیقه‌ای؛ لحظهٔ تأیید، **بسته از نو راستی‌آزمایی و اعتبارسنجی می‌شود** (پوشه ممکن است عوض شده باشد)؛ فایل نوشته می‌شود و بلافاصله **غیرفعال** می‌شود (`.disabled-<name>.md` — لودر آن را نادیده می‌گیرد). فعال‌سازی فقط با `/skill enable <نام>` و تصمیم صریح مالک.

## بررسی سطح حمله (مرز اعتماد این آیتم)

مهارت وارداتی = **محتوای پرامپتِ نوشته‌شده توسط شخص ثالث**. بدنهٔ مهارت وارد system prompt می‌شود، پس بستهٔ مخرب = بردار تزریق پرامپت. لایه‌های دفاعی، به ترتیب:

1. **checksum** — فقط دست‌کاریِ حین انتقال را لو می‌دهد. هرکسی می‌تواند بستهٔ معتبر بسازد؛ checksum سالم ≠ نویسندهٔ قابل اعتماد. این آگاهانه «امضا» نیست.
2. **خط لولهٔ فاز ۳، کامل و بدون میان‌بُر** — سقف ۶۴KB، پارس strict، اسکن تزریق (فارسی+انگلیسی) و شبه‌رمز، و برای فرم نشانی همان محافظ SSRF (resolve+classify هر هاپ، پین سوکت، اعتبارسنجی مجدد ریدایرکت).
3. **کارت بررسی اجباری** — هیچ مسیری (حتی دانگرید) بدون تأیید صریح مالک نصب نمی‌شود؛ هشدارها جلوی چشم‌اند، نه لاگ.
4. **غیرفعالِ پیش‌فرض** — مهارت وارداتی حتی بعد از تأیید، خاموش می‌ماند تا مالک جداگانه فعالش کند.
5. **فقط مالک** — کل سطح `/skill` (از جمله export/import) با همان گیت دومرحله‌ای فاز ۳ قفل است؛ دکمه‌های تأیید هم مالکیت را دوباره چک می‌کنند.

**قاعدهٔ طلایی برای مالک: بسته را فقط از منبعی وارد کن که به آن اعتماد داری.** کارت بررسی را واقعاً بخوان — مخصوصاً هشدارها و ۲۰ خط اول بدنه را.

## آگاهانه بیرون گذاشته شد (نامزد فاز ۵)

- **امضای دیجیتال واقعی** (کلید عمومی/خصوصی، زنجیرهٔ اعتماد نویسنده): checksum فقط یکپارچگی است، نه احراز هویت.
- **مارکت‌پلیس عمومی / اشتراک‌گذاری همگانی**: این آیتم فقط «شخصی» است — انتقال دستی فایل بین نمونه‌های خودت.
- **به‌روزرسانی خودکار** از روی نسخه: ارتقا همیشه دستی و با کارت بررسی است.
