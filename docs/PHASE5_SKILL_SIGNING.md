# امضای بستهٔ مهارت و ناشران مورداعتماد (فاز ۵، آیتم ۱)

> بستهٔ `.bobiskill` حالا می‌تواند امضای دیجیتال ed25519 داشته باشد؛ مالک جفت‌کلید می‌سازد،
> با همان کلید امضا می‌کند، و فهرستی از ناشران مورداعتماد نگه می‌دارد.
> امضا «کی امضا کرده» را ثابت می‌کند؛ «به کی اعتماد داری» فقط از فهرست مالک می‌آید.

## دستورها (فقط مالک — همه زیر `/skill` که از قبل owner-only است)

| دستور | اثر |
|---|---|
| `/skill keygen [--force]` | ساخت جفت‌کلید ed25519؛ کلید خصوصی فقط در دیتابیس همین نمونه می‌ماند |
| `/skill keyexport` | دریافت کلید خصوصی به‌صورت فایل (بکاپ) — تنها مسیری که کلید از ذخیره خارج می‌شود |
| `/skill export <نام> [--sign\|--no-sign]` | صدور بسته؛ وقتی کلید هست به‌طور پیش‌فرض امضا می‌شود |
| `/skill trust <شناسه‌کلید\|کلیدعمومی> [برچسب]` | افزودن ناشر به فهرست اعتماد |
| `/skill untrust <شناسه‌کلید>` | لغو اعتماد (revocation) |
| `/skill trusted` | فهرست ناشران مورداعتماد |
| `/skill list` | مهارت‌های نصب‌شده با وضعیت امضا؛ امضایِ ناشرِ بی‌اعتماد پرچم می‌خورد |
| `/skill import …` | بدون تغییر در سینتکس؛ کارت بررسی حالا وضعیت امضا را نشان می‌دهد |

## قالب بسته (`.bobiskill` — نسخهٔ فرمت همان ۱)

بلوک `signature` اختیاری و افزایشی است؛ خواننده‌های قدیمی آن را نادیده می‌گیرند و checksum
شان همچنان معتبر است (checksum بلوک امضا را پوشش نمی‌دهد):

```jsonc
{
  "format": "bobi-skill-package",
  "formatVersion": 1,
  "skill": { /* مثل فاز ۴ */ },
  "metadata": { /* مثل فاز ۴ */ },
  "signature": {                       // اختیاری
    "alg": "ed25519",
    "keyId": "…",                      // اثر انگشت SHA-256 کلید عمومی (۶۴ رقم hex) = شناسهٔ ناشر
    "publicKey": "…",                  // کلید عمومی خام ۳۲بایتی، base64
    "sig": "…"                         // امضای ed25519 روی بایت‌های payload کانونیکال، base64
  },
  "checksum": "sha256 hex روی فرم کانونیکال"
}
```

- **امضا دقیقاً همان بایت‌هایی را پوشش می‌دهد که checksum پوشش می‌دهد** (رشتهٔ کانونیکال
  `canonicalPayload`)؛ پس یک امضا = اصالت کل بسته (بدنهٔ مهارت، نسخه، توضیح، متادیتا).
- `keyId` هنگام راستی‌آزمایی از نو از `publicKey` محاسبه و با `keyId` ادعاشده مقایسه می‌شود؛
  پیوند زدن امضای معتبر زیر شناسهٔ ناشر دیگر ممکن نیست.
- امضای خراب/ناقص = **رد قطعی** (`bad_signature`)؛ حالت «امضای نامعتبر ولی قابل وارد کردن» وجود ندارد.

## جریان وارد کردن

1. **راستی‌آزمایی** (`verifySkillPackage`): سقف حجم، JSON، نشانگر فرمت، checksum، سپس —
   اگر بلوک امضا هست — شکل بلوک، الگوریتم، پیوند keyId↔publicKey، و خود امضا.
2. **اعتبارسنجی** (`planSkillImport`): همان خط لولهٔ فاز ۳/۴، بدون هیچ میان‌بری.
3. **کارت بررسی**: یک خط وضعیت امضا بالای کارت:
   - `✅ امضا: «برچسب» — ناشر مورداعتماد` (امضای معتبر + کلید در فهرست اعتماد) →
     کارت **فشرده** (پیش‌نمایش ۵ خط به‌جای ۲۰)؛ گیت تأیید، راستی‌آزماییِ لحظهٔ تأیید، و
     غیرفعالِ پیش‌فرض سر جایشان‌اند — فقط اصطکاک خواندن کمتر است.
   - `✏️ امضا شده با کلید ناشناس …` (امضای معتبر ولی ناشر ناشناس) → کارت کامل.
   - `⚠️ بدون امضا` → کارت کامل + تأیید فقط با تصمیم صریح مالک.
4. **تأیید** (`approvePendingImport`): بسته از نو راستی‌آزمایی می‌شود (اعتماد هم از نو
   حل می‌شود — اگر بین کارت و تأیید untrust کرده باشی اثر می‌کند)؛ امضاکنندهٔ
   راستی‌آزمایی‌شده در `skill_install_provenance` ثبت می‌شود؛ مهارت **غیرفعال** نصب می‌شود.

## فهرست اعتماد و لغو

- `skill_trusted_publishers`: `key_id → (label, public_key)`؛ اعتماد فقط از همین جدول می‌آید،
  هرگز از کلید داخل بسته.
- لغو = حذف سطر (`/skill untrust`). سطر provenance پاک نمی‌شود تا `/skill list`
  مهارت‌های نصب‌شده از آن ناشر را با `⚠️ امضا معتبر ولی ناشر در فهرست اعتماد نیست` پرچم بزند؛
  تصمیم (غیرفعال/حذف) با مالک است. حذف مهارت (`/skill uninstall`) سطر provenance را هم پاک می‌کند.

## ذخیره‌سازی کلید

- `skill_signing_key` (تک‌سطر): `key_id`، `public_key`، و `private_key_jwk`.
- کلید خصوصی هرگز لاگ نمی‌شود، در هیچ پاسخی (به‌جز `/skill keyexport`) برنمی‌گردد، و هیچ
  مسیر خودکاری آن را ارسال نمی‌کند. محافظتِ در حال استراحت = خودِ فایل دیتابیس
  (همان ردهٔ محتوای گفتگوها) — بررسی سطح حمله را پایین ببین.

## بررسی سطح حمله (مرز اعتماد این آیتم)

1. **امضا ≠ اعتماد.** امضای معتبر فقط می‌گوید «دارندهٔ کلید خصوصی این بایت‌ها را امضا کرده».
   اعتماد به «ناشرِ پشت کلید» فقط از فهرست مالک می‌آید. بستهٔ خودامضاشدهٔ مهاجم همیشه
   «کلید ناشناس» نشان داده می‌شود، هرگز «مورداعتماد».
2. **کلید خصوصی در دیتابیس به‌صورت متن ساده است.** آگاهانه: بدون master keyِ پیکربندی‌شده،
   رمزنگاریِ واقعی ممکن نبود و keygen نباید به متغیر محیطی گره بخورد. پیامد: هرکس فایل
   `bobi.db` را بخواند می‌تواند به نام مالک امضا کند — همان سطح دسترسی‌ای که محتوای
   گفتگوها را هم می‌خواند. اگر master key بعداً آمد، مسیر ارتقا: ستون به envelope
   AES-256-GCM (همان شکل `secret_store.ts`) مهاجرت کند.
3. **غیرقابل جعل بودن امضا.** ed25519 قطعی و non-malleable است: برای یک کلید و پیامِ ثابت
   دقیقاً یک امضای معتبر وجود دارد؛ پس `bad_signature` همیشه یعنی دست‌کاری یا کلید اشتباه،
   نه «بدشانسی رمزنگاری».
4. **حملهٔ دانگرید.** نسخهٔ قدیمیِ امضاشده، امضای معتبر دارد — امضا «تازه بودن» را ثابت
   نمی‌کند. دفاع همان هشدار صریح دانگرید فاز ۴ روی کارت بررسی است (امضا آن را دور نمی‌زند).
5. **تعویض بسته بین کارت و تأیید.** `packageText` لحظهٔ تأیید از نو راستی‌آزمایی می‌شود
   (checksum + امضا)؛ دست‌کاریِ میانی = رد.
6. **چرخش کلید.** `/skill keygen --force` شناسهٔ تازه می‌سازد؛ بسته‌های قبلی چون کلید
   عمومی را در خودشان دارند همچنان راستی‌آزمایی می‌شوند — اما دیگر «مورداعتماد» نیستند
   مگر شناسهٔ تازه trust شود.
7. **فقط مالک.** کل سطح `/skill` (از جمله keygen/keyexport/trust) با همان گیت مالک قفل است؛
   دکمه‌های تأیید هم مالکیت را دوباره چک می‌کنند. `keyexport` سندی با کپشن هشدار می‌فرستد.

## نقطه‌های اتصال مارکت‌پلیس آینده (عمداً ساخته نشد)

- `keyId` شناسهٔ پایدار و سراسریِ ناشر است (اثر انگشت کلید، نه نام کاربریِ یک سرور).
- بسته خودتوصیف است: `signature.publicKey` اجازهٔ راستی‌آزمایی بدون تماس با هیچ سروری می‌دهد؛
  «اعتماد» لایهٔ جداست (رجیستری محلی امروز، دایرکتوری ناشران فردا).
- قرارداد راستی‌آزمایی در `checkSignatureBlock` مستند و خالص است — یک سرور مارکت‌پلیس
  می‌تواند همان تابع را روی بسته‌های آپلودشده اجرا کند.
- `SkillTrust` (اینترفیس در `cmd_phase3_skills.ts`) مرز انتزاع است: امروز روی SQLite،
  فردا روی کشِ دایرکتوری مارکت‌پلیس + امضای خودِ دایرکتوری.
- مهاجرتِ فرمت: چون `formatVersion` همان ۱ ماند و بلوک امضا افزایشی است، مارکت‌پلیس
  می‌تواند فیلدهای تازه (مثل `marketplace: {listingId, …}`) را بدون شکستن خواننده‌های
  فعلی اضافه کند — به شرطی که داخل بایت‌های امضاشده نباشند، یا نسخهٔ فرمت بالا برود.

## آگاهانه بیرون گذاشته شد

- **مارکت‌پلیس عمومی**: این آیتم فقط «شخصی + اعتماد دستی» است — هیچ سرور، لیستینگ، یا
  دانلود خودکاری ساخته نشد.
- **زنجیرهٔ اعتماد / گواهی**: اعتماد مسطح و دستی است (فهرست مالک)؛ بدون CA و بدون وبِ اعتماد.
- **امضای چندگانه / آستانه**: هر بسته یک امضا دارد.
- **رمزنگاری کلید خصوصی با master key**: به‌خاطر نبود master key در استقرار فعلی،
  به «فایل دیتابیس = مرز» بسنده شد (بند ۲ سطح حمله).
