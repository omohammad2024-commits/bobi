# دستورهای اتوماسیون هرمس (فاز commands-auto)

۱۹ دستور از نگاشت هرمس در `src/bot/cmd_auto.ts` پیاده شده است؛ رشته‌ها در
`src/bot/cmd_auto_strings.ts` و تست‌ها در `tests/cmd_auto.test.ts`.
ثبت در بات، منو و `/help` با هماهنگ‌کننده است.

## دستورهای کاربر

| دستور | کار |
|---|---|
| `/bg <متن>` | اجرای پرامپت در پس‌زمینه (بدون انتظار)؛ نتیجه با پیام جدا می‌آید. `list` و `cancel <id>`. سقف ۳ کار هم‌زمان برای هر کاربر. |
| `/btw <سؤال>` | پرسش جانبی در یک گفتگوی جداگانه (`btw:<userId>:<ts>`)؛ رشتهٔ اصلی دست‌نخورده می‌ماند. شناسهٔ گفتگوی جانبی اعلام می‌شود. |
| `/queue <متن>` | ذخیرهٔ پرامپت در صف این گفتگو. `list` و `clear`. |
| `/steer <راهنما>` | اگر نوبتی در این چت در حال اجراست، راهنما به‌عنوان «در انتظار» ذخیره می‌شود؛ وگرنه فوراً یک نوبت با همان متن اجرا می‌شود. |
| `/agents` | کارهای پس‌زمینهٔ شما، نوبتِ در حال اجرای این چت، راهنمای در انتظار، و در دسترس بودن ابزار delegate. |
| `/suggestions` | پیشنهاد اتوماسیون از روی پیام‌های اخیر (ابتکاری و ساده، با برچسب مشخص). |
| `/blueprint list` | سه قالب آماده: `morning_digest`، `reminder`، `weekly_review`. |
| `/blueprint run <نام> [آرگومان]` | ساخت قالب. `reminder` به شکل `reminder <دقیقه> <متن>`. |
| `/refine` | بازبینی تاریخچهٔ همین گفتگو و ذخیرهٔ درس‌های ماندگار با ابزار remember. |
| `/review <موضوع>` | بازبینی مستقل توسط ایجنت فرزند (ابزار delegate). |
| `/plan <هدف>` | فقط طرح مرحله‌به‌مرحله؛ بدون اجرا. |
| `/moa <سؤال>` | مشورت هم‌زمان با چند مدل (ابزار consult_models). |
| `/memory list [n]` / `search <عبارت>` / `del <کلید>` | مدیریت حافظهٔ بلندمدتِ خودِ کاربر. |
| `/bundles list` / `use <نام>` | بسته‌های پیشنهادی ابزار (`research`، `memory`، `media`، `planning`)؛ `use` فقط نام را در ترجیحات ذخیره می‌کند (توصیه‌ای). |

## دستورهای مالک

| دستور | کار |
|---|---|
| `/goal set <متن>` / `show` / `clear` | هدف‌های ماندگار (روی ابزارهای add_goal/list_goals/complete_goal). |
| `/subgoal add <شناسهٔ والد> <متن>` / `list [شناسهٔ والد]` / `clear <شناسهٔ والد>` | زیرهدف = هدفی که عنوانش با `↳ <عنوان والد> — ` شروع می‌شود (قرارداد نام‌گذاری، چون اسکیما زیرهدف ندارد). |
| `/heartbeat status` | وضعیت سرویس ضربان (اگر هماهنگ‌کننده گزارشش را وصل کرده باشد) + شمار یادآورهای `heartbeat:`. |
| `/heartbeat every <فاصله> <متن>` | ساخت یادآور دوره‌ای به‌صورت وظیفهٔ زمان‌بندی‌شده (اکشن agent). فاصله مثل `30m`، `2h`، `1d`. |
| `/loop every <فاصله> <متن>` / `stop <id>` | حلقهٔ تکراری = وظیفهٔ زمان‌بندی‌شده؛ توقف با شناسه. |
| `/cron list` / `add <عبارت کرون> <متن>` | وظایف زمان‌بندی‌شده (اکشن message به همین چت). |
| `/learn <نام> \| <توضیح>` | پیش‌نویس مهارت (markdown)؛ به‌صورت فایل برای مالک فرستاده می‌شود تا خودش در پوشهٔ مهارت‌ها بگذارد. نام فقط `a-z0-9-`. |

## محدودیت‌های صادقانه

- **تخلیهٔ خودکار صف (`/queue`)**: صف ذخیره/list/clear می‌شود، ولی چسباندن خودکار آن به پیام بعدی کاربر نیازمند اتصال به مسیر پیام موتور گفتگوست (پیگیری با هماهنگ‌کننده). چیزی جعل نشده؛ در پاسخ دستور هم گفته می‌شود.
- **تزریق راهنمای در انتظار (`/steer`)**: راهنما ذخیره و در `/agents` نمایش داده می‌شود، ولی تزریق خودکار به پیام بعدی همان اتصال موتور را می‌خواهد.
- **«بدون ابزار» در `/plan`**: در سطح پرامپت اعمال می‌شود؛ `ConversationInput` قلابی برای بستن ابزار ندارد. نوبت با دسترسی‌های عادی خودِ کاربر اجرا می‌شود، پس چیزی فراتر از اختیار او اجرا نمی‌شود.
- **نوشتن فایل در `/learn`**: این ماژول به پوشهٔ پیکربندی‌شدهٔ مهارت‌ها دسترسی ندارد؛ پیش‌نویس به‌صورت سند تحویل داده می‌شود.
- **قلب جهانی (`/heartbeat status`)**: نمونهٔ سرویس در سیم‌کشی فرایند است؛ این ماژول یک ارائه‌دهندهٔ اختیاری (`setHeartbeatInfoProvider`) دارد که هماهنگ‌کننده می‌تواند وصل کند. بدون آن، وضعیت «نامشخص» گزارش می‌شود.
- **`/blueprint run` برای غیرمالک**: قالب‌های `morning_digest` و `weekly_review` به ابزار `schedule_task` نیاز دارند که فقط مالک است — درخواست غیرمالک با پیام روشن رد می‌شود. قالب `reminder` از `remind_at` استفاده می‌کند که مالک‌اختصاصی نیست.

## SECURITY — سطح حمله

۱. **ساخت اکتور سمت سرور**: اکتور ابزار همیشه از `from.id`ی معتبر و از طریق Authorization Core ساخته می‌شود (`actorForTelegramUser`)؛ متن پیام هیچ‌وقت اختیار را زیاد نمی‌کند. شناسه‌ای که کاربر بدهد هرگز برای احراز هویت استفاده نمی‌شود.
۲. **دفاع دو‌لایه برای مالک**: دستورهای مالک در لایهٔ بات با `isOwnerSender` رد می‌شوند و پل احراز هویت هم کلیدهای ابزارهای مالک‌اختصاصی را از غیرمالک می‌گیرد؛ حتی اکتوری که دستی ساخته شود نمی‌تواند `schedule_task` یا `add_goal` را اجرا کند.
۳. **جداسازی هر کاربر**: کارهای پس‌زمینه، صف‌ها، راهنماهای در انتظار و حافظه همه با شناسهٔ فرستنده کلید می‌خورند. `list` کاربر A هیچ‌وقت کاربر B را نمی‌بیند (تست شده).
۴. **اعتبارسنجی ورودی**: متن آزاد trim و سقف طول می‌خورد (پرامپت ۲۰۰۰، آیتم صف ۲۰۰۰، فاصلهٔ `/learn` با رجکس نام) پیش از رسیدن به ابزار یا موتور؛ موتور/ابزار آن را داده می‌دانند، نه دستور.
۵. **`/bg`**: نتیجه فقط به همان چتِ درخواست‌کننده تحویل داده می‌شود؛ چتِ حذف‌شده فقط لاگ می‌شود و رها می‌گردد. لغو، پرچم وضعیت را عوض می‌کند و تحویل بعدی را ساکت نگه می‌دارد.
۶. **ابزارهای مالک‌اختصاصی از مسیر غیرمالک**: `/blueprint run morning_digest` برای غیرمالک پیش از صدا زدن ابزار رد می‌شود و پیامش دلیل را می‌گوید.
۷. **بدون نشت راز**: هیچ پاسخی پیکربندی، توکن یا خروجی خام ابزار را نشان نمی‌دهد؛ خطاها به پیام‌های کوتاه کاربرپسند خلاصه می‌شوند.
