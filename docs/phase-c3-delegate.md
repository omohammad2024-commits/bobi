# فاز C3 — ابزار `delegate` (ایجنت فرزند)

ابزار `delegate` یک زیروظیفهٔ مستقل را به یک `AgentLoop` تازه با رجیستری ابزار
فیلترشده و بودجهٔ محدود می‌سپارد و خلاصهٔ فارسی برمی‌گرداند. برای کارهای فرعی
که نباید زمینهٔ گفتگوی اصلی را شلوغ کند.

قرارداد در `tests/delegate.test.ts` پین شده است.

## ورودی / خروجی

| فیلد | نوع | سقف |
|---|---|---|
| `task` | رشته، الزامی | ۱ تا ۲۰۰۰ نویسه |
| `maxIterations` | عدد صحیح، اختیاری | ۱ تا ۳ (پیش‌فرض ۳) |
| `maxToolCalls` | عدد صحیح، اختیاری | ۱ تا ۵ (پیش‌فرض ۵) |

خروجی موفق: `{ ok: true, summary }` — خلاصه حداکثر ۲۰۰۰ نویسه؛ اگر کوتاه شود،
یادداشت نام‌دار `[یادداشت: پاسخ فرزند بلند بود و کوتاه شد]` به انتهایش اضافه
می‌شود. خطای فرزند: `{ ok: false, error }` با پیام فارسی ثابت و امن — هیچ‌وقت
متن خام خطا (payload پروایدر، stack trace) به بیرون درز نمی‌کند.

## سقف‌های ثابت (مستقل از ورودی)

- `DELEGATE_TOTAL_TIMEOUT_MS = 60_000` — سقف کل اجرای فرزند
- `DELEGATE_CALL_TIMEOUT_MS = 20_000` — سقف هر فراخوانی پروایدر در حلقهٔ فرزند
- `DELEGATE_SUMMARY_MAX_CHARS = 2000` — سقف طول خلاصه

همهٔ این‌ها زیر سقف‌های معمول والد هستند (۶ دور / ۱۲ فراخوانی / ۱۲۰ ثانیه).

## مدل امنیتی

1. **عمق ۱ ساختاری، نه شمارنده.** رجیستری فرزند با `createChildToolService()`
   از رجیستری والد ساخته می‌شود **منهای خود `delegate`** — فقط با API عمومی
   `ToolService` (سازنده + `registry.list()`). مدل فرزند اصلاً از وجود
   `delegate` باخبر نمی‌شود (`toolSpecsFor` آن را حذف می‌کند) و درخواست مستقیم
   هم با `not_found` رد می‌شود. بمب بازگشتی از نظر ساختاری غیرممکن است؛ هیچ
   شمارنده‌ای نیست که مدل بتواند روی آن اثر بگذارد.
2. **همان actor، بدون ارتقای دسترسی.** حلقهٔ فرزند با `ctx.actor` اجرا می‌شود —
   همان هویتی که فراخوانی والد با آن مجاز شده بود. دیده‌شدن ابزارها و هر اجرا،
   دقیقاً مثل ابزارهای خود والد، با همین هویت کنترل می‌شود.
3. **خروجی فرزند دادهٔ نامعتبر است.** خلاصه داخل `data` برمی‌گردد و حلقهٔ والد
   طبق قرارداد همیشگی آن را در `<tool_result>` می‌پیچد؛ system prompt از قبل
   اعلام کرده چنین محتوایی داده است، نه دستور.
4. **مجوز `tools:delegate`، بدون `ownerOnly`.** کاربران تأییدشده هم می‌توانند
   واگذار کنند؛ امنیت از ساختار بالا می‌آید، نه از محدودکردن به مالک. پل
   `authorizeToolUse` این کلید را مثل بقیهٔ ابزارها خودکار اعطا می‌کند.

## ثبت در `src/index.ts`

`delegate` به خودِ `ToolService` والد نیاز دارد، پس **بعد** از ساخته‌شدن
`tools` (و `gateway`) ثبت می‌شود — نه داخل آرایهٔ `extraTools`:

```ts
import { createDelegateTool } from "./tools/delegate";

// بعد از: const gateway = new AiGateway({ storage, adapters, secrets });
tools.registry.register(
  createDelegateTool({
    tools,
    provider,
    model: selection ? selection.modelId : config.aiModel,
  }) as Tool<unknown, unknown>,
);
```
