# حالت دستیار گروهی (Phase-3 Item 2)

> وضعیت: پیاده‌سازی کامل در `src/groups/assistant.ts` (+ `assistant_strings.ts`)؛
> ثبت دستورها و هوک پیام در `src/index.ts`/`src/bot/bot.ts` **با هماهنگ‌کننده است**
> (این ماژول هیچ‌یک از آن فایل‌ها را لمس نمی‌کند).

## چی ساخته شد

یک «حالت دستیار» اختیاری برای هر گروه (پیش‌فرض: **خاموش**). وقتی مالک برای
گروهی روشنش کند:

1. **سکوت پیش‌فرض (reply-only-when-called)** — بابی روی چت عادی گروه ساکت
   می‌ماند و فقط وقتی جواب می‌دهد که منشن شود (`@Bobi_Agentbot`) یا به پیامش
   ریپلای شود. این رفتار پیش‌فرضِ حالت است (ضد نویز)؛ مالک می‌تواند با
   `replyOnlyWhenCalled: false` آن را شل کند.
2. **خلاصهٔ بحث (`/gsummary`)** — خلاصهٔ آماری و قطعی (بدون مدل زبانی):
   تعداد پیام، تعداد نفرات، بازهٔ زمانی، فعال‌ترین‌ها، پرتکرارترین واژه‌ها.
   هر عضو گروه می‌تواند بگیرد (وقتی حالت روشن است)؛ خروجی فقط در همان گروه
   پست می‌شود.
3. **نظرسنجی (`/gpoll "سوال" "گزینه۱" "گزینه۲" ...`)** — نظرسنجی بومی تلگرام،
   فقط مالک، ۲ تا ۱۰ گزینه، با سقف‌های تلگرام (سوال ≤ ۳۰۰ حرف، گزینه ≤ ۱۰۰ حرف).
4. **تنظیمات** — `/gassistant on|off|status` فقط مالک؛ ذخیره‌سازی با همان الگوی
   مدیریت (`user_prefs` زیر شناسهٔ **مالک** با کلید `gacfg:<chatId>`).

کلیدهای پیکربندی: `enabled` (پیش‌فرض false)، `replyOnlyWhenCalled` (پیش‌فرض true)،
`summaryMaxMessages` (۵ تا ۵۰، پیش‌فرض ۳۰)، `pollsAllowed` (پیش‌فرض true).

## مالک چطور فعال می‌کند

```
(در گروه)  /gassistant on        → روشن شدن برای همان گروه
           /gassistant status    → نمایش وضعیت
           /gassistant off       → خاموش شدن
           /gsummary             → خلاصهٔ بحث اخیر (هر عضو گروه)
           /gpoll "ناهار چی بخوریم؟" "پیتزا" "کباب"   → نظرسنجی بومی
```

## نکات اتصال برای هماهنگ‌کننده (wiring)

این ماژول فقط منطق خالص + هندلرهای قابل تست صادر می‌کند؛ سه کار با هماهنگ‌کننده:

1. **ثبت دستورها** (در `src/index.ts`، کنار بقیهٔ دستورها): `bot.command("gassistant" | "gsummary" | "gpoll", ...)` —
   هر سه با همان گیت‌های مسیر پیام (`gateGroup` + `gateUser`) و گیت سطح
   (`requireOwnerTier` برای `gassistant` و `gpoll`؛ `gsummary` عمومیِ درون‌گروهی
   است چون حالت روشن بودن یعنی مالک آن را برای گروه خواسته). هر سه در
   `COMMAND_HELP` با `ownerOnly: true` ثبت شوند تا در منو/پالت عمومی نامرئی
   بمانند (حتی `gsummary` — نامرئی بودن جایگزین گیت نیست، ولی UX یکدست می‌ماند).
2. **هوک سکوت** در هندلر `message:text` (در `src/bot/bot.ts`): قبل از `runTurn`،
   برای چت‌های group/supergroup —
   ```ts
   const cfg = getAssistantConfig(deps.storage, ownerId, chatId);
   const replyToBot = ctx.message.reply_to_message?.from?.id === botId;
   if (!shouldReplyAssistant({ text, botUsername, replyToBot, enabled: cfg.enabled, replyOnlyWhenCalled: cfg.replyOnlyWhenCalled }))
     return; // ساکت بمان — ولی recordGroupMessage پایین هنوز اجرا شود
   ```
3. **هوک ثبت تاریخچه**: برای پیام‌های متنی گروه‌ها، `recordGroupMessage(env, { chatId, userId, name, text, tsMs })`
   صدا زده شود (فقط وقتی حالت روشن است چیزی ذخیره می‌شود؛ خود تابع این را چک می‌کند).
   `env` موردنیاز هندلرها: `{ storage, ownerId, isOwner?, botUsername, history }`.

## بررسی سطح حمله

| بردار | وضعیت |
|---|---|
| عضو گروه می‌خواهد حالت را روشن کند | رد مؤدبانه؛ پیکربندی زیر شناسهٔ مالک ذخیره می‌شود و هندلر مالکیت را سرورساید دوباره چک می‌کند (دفاع در عمق با گیت ثبت دستور) |
| خواندن پیکربندی مالک توسط عضو | هیچ خروجی‌ای پیکربندی را به غیرمالک نشان نمی‌دهد؛ `/gassistant status` مالک‌گیت است |
| تزریق دستور در متن خلاصه‌ساز | خلاصه‌ساز مدل زبانی ندارد — خروجی همیشه قالب آماری ثابت است؛ ورودی‌ها سقف دارند (پیام ≤ ۲۰۰۰ حرف، خلاصه ≤ ۵۰ پیام)؛ نام‌های نمایشی یک‌خطی و کوتاه می‌شوند؛ متن خام پیام‌ها هرگز نقل‌قول نمی‌شود |
| نشت محتوای گروه به بیرون | بافر تاریخچه فقط در حافظه است (با ری‌استارت پاک می‌شود)، کلیدخورده با chatId، و خلاصه فقط به همان گروه برمی‌گردد؛ هیچ مسیری به مالک/چت دیگر وجود ندارد |
| فلاد کردن بافر خلاصه | سقف ۱۰۰ پیام به‌ازای هر گروه و ۱۰۰ گروه؛ متن‌های دستوری (`/...`) ثبت نمی‌شوند |
| جعل منشن (`@Bobi_Agentbot_fan`) | مرزهای `\p{L}\p{N}_` — فقط منشن دقیق (غیرحساس به حروف) قبول می‌شود |

## عمداً بیرون گذاشته شده

- **خلاصهٔ هوشمند با مدل زبانی**: عمداً آماری و قطعی نگه داشته شد — هم برای
  امنیت (بدون سطح تزریق پرامپت) و هم برای هزینه/تأخیر صفر. اگر روزی مدل لازم شد،
  باید با همان قرارداد ضدتزریق (ورودی به‌عنوان داده، سقف طول، خروجی فقط در گروه)
  بازطراحی شود.
- **نقش «ادمین مجازشده توسط مالک»**: تسک با علامت سؤال مطرحش کرده بود؛ تصمیم:
  فقط مالک. `/gsummary` برای همهٔ اعضای گروهِ روشن باز است (نکتهٔ ویژگی همین است)،
  ولی هر چیز مدیریتی (`gassistant`، `gpoll`) صرفاً مالک — بدون لایهٔ نقش اضافه.
- **دکمه‌های شیشه‌ای/پنل تنظیمات**: فعلاً فقط دستوری؛ پنل می‌تواند بعداً اضافه شود.
- **ذخیرهٔ دائمی تاریخچه**: بافر عمداً در حافظه است؛ ماندگاری یعنی مسئولیت حریم
  خصوصی بیشتر — اگر لازم شد، با رمزنگاری و TTL جداگانه طراحی شود.
- **ثبت دستورها و هوک `message:text`**: با هماهنگ‌کننده (نباید این فاز فایل‌های
  مشترک را لمس می‌کرد).
