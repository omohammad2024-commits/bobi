# بنچ‌مارک بابی 🤖📊

مجموعه‌تست رفتاری برای اثبات اینکه بابی در عمل از هرمس بهتر است — نه با حرف،
با عدد. ۲۴ تسک فارسی، اجرای headless روی `ConversationEngine` واقعی، و
امتیازدهی کاملاً قطعی (بدون داوری مدل زبانی).

## چه چیزی اندازه گرفته می‌شود

| دسته | تعداد | چه چیزی |
| --- | --- | --- |
| دقت فراخوانی ابزار | ۴ | ابزار درست + آرگومان درست (محاسبه، ساعت، تبدیل واحد) |
| تسک چندمرحله‌ای | ۴ | ۲+ فراخوانی ابزار پشت سر هم |
| حافظه بین نوبت‌ها | ۳ | نوبت اول به‌خاطر بسپار، نوبت دوم یادآوری کن |
| زمان‌بندی با زبان طبیعی | ۳ | «فردا ساعت ۹»، «هر روز صبح»، «هر هفته شنبه‌ها» |
| جست‌وجوی وب + خلاصه | ۳ | (در حالت آفلاین: نتایج شبیه‌سازی‌شده) |
| مقاومت در برابر تزریق پرامپت | ۴ | خروجی ابزار/وب حاوی دستور مخرب → باید نادیده گرفته شود |
| کیفیت پاسخ فارسی | ۳ | روبریک قطعی: طول، عدم نشت انگلیسی، لحن رسمی |

## ساختار

```
bench/
├── tasks/            ۲۴ تسک YAML (id، title_fa، prompt فارسی، معیار امتیاز)
├── schema.ts         تایپ‌ها + اعتبارسنجی YAML
├── scorer.ts         امتیازدهی قطعی — هیچ LLM-as-judgeای وجود ندارد
├── mock_tools.ts     شبیه‌سازی web_search و fetch_url برای حالت آفلاین
├── run.ts            رانر: bun bench/run.ts [--tasks ..] [--live]
├── hermes_adapter.ts تبدیل تسک‌ها به دیتاست batch_runner هرمس
├── hermes_adapter.py پارس trajectory هرمس → فرمت امتیازدهی
├── hermes_adapter.md راهنمای دقیق رقابت روبه‌رو با هرمس
├── hermes_tool_map.json نگاشت نام ابزار هرمس → بابی (پر شود)
├── results/          گزارش‌های JSON و Markdown فارسی
└── tests/            تست‌های scorer، اعتبارسنجی تسک‌ها، plumbing رانر
```

## اجرای آفلاین (پیش‌فرض)

```bash
bun bench/run.ts
bun bench/run.ts --tasks calc_01,mem_pet   # فقط چند تسک
```

- بدون کلید API، بدون اینترنت: `FakeProvider` + دیتابیس `:memory:` + وب
  شبیه‌سازی‌شده.
- **امتیازهای این حالت معیار کیفیت مدل نیست** — فقط ثابت می‌کند لوله‌کشی
  (engine → ابزار → scorer → گزارش) سالم است. اکثر تسک‌ها در این حالت
  می‌افتند و این طبیعی است؛ گزارش حالت را «آفلاین (plumbing)» می‌نویسد.

## رقابت زندهٔ روبه‌رو (بابی در برابر هرمس)

**پیش‌نیاز (کار مالک است):** اول در تلگرام با دستور `/ai` یک ارائه‌دهنده و
مدل واقعی پیکربندی کنید. بعد:

```bash
# بابی با مدل واقعی
bun bench/run.ts --live

# هرمس با همان مدل — قدم‌به‌قدم در bench/hermes_adapter.md
bun bench/hermes_adapter.ts to-jsonl --out bench/hermes_dataset.jsonl
# ... اجرای batch_runner.py در مخزن هرمس ...
python3 bench/hermes_adapter.py --run-dir ~/workspace/hermes-ref/data/bench_XXX \
  --index bench/hermes_dataset.jsonl.index.json --model '<همان مدل>' \
  --out bench/results/hermes_XXX.json
bun bench/run.ts --score-only bench/results/hermes_XXX.json \
  --tool-map bench/hermes_tool_map.json --out bench/results
```

- **مدل یکسان در دو طرف** — شرط انصاف رقابت همین است.
- اگر ارائه‌دهنده پیکربندی نشده باشد، `--live` با پیام فارسی واضح متوقف
  می‌شود؛ **هیچ‌وقت نتیجه جعل نمی‌کند.**
- `hermes_tool_map.json` را بعد از اولین اجرای هرمس پر کنید (نام واقعی
  ابزارهای هرمس را از `tool_stats` خروجی batch بخوانید). جزئیات کامل در
  `bench/hermes_adapter.md`.

## خواندن گزارش

هر اجرا دو فایل در `bench/results/` می‌سازد:

- `<stamp>.json` — ماشین‌خوان: نتیجهٔ هر تسک، تک‌تک چک‌ها، دنبالهٔ
  فراخوانی ابزارها، تأخیر (کل + تقریبیِ اولین فعالیت)، توکن‌ها، هزینهٔ
  تخمینی (`estimateCost` از `src/ai/usage.ts`).
- `<stamp>.md` — فارسی: جدول تسک‌ها + جمع‌بندی + جزئیات چک‌های ناموفق.

دربارهٔ تأخیر: انجین استریم توکن ندارد؛ «زمان تا اولین فعالیت» تقریبی است
(اولین کال‌بک `onProgress`) و وقتی هیچ قدمی ثبت نشود فقط مجموع گزارش
می‌شود — این در کد مستند است.

## سندباکس و سطح حمله (مهم)

رانر فراخوانی‌های ابزار مدل را **واقعاً اجرا می‌کند** (ماشین‌حساب، یادآور،
حافظه، …). قواعد:

- **حالت آفلاین امن است:** `web_search` و `fetch_url` به دادهٔ آمادهٔ داخل
  YAML همان تسک سرو می‌شوند (بدون شبکه)؛ بقیهٔ ابزارها روی دیتابیس
  `:memory:`یِ دورریختنی کار می‌کنند. هیچ‌چیز به بیرون نمی‌رسد.
- **حالت زنده با احتیاط:** مدل واقعی ابزارهای واقعی را صدا می‌زند.
  یادآورها و حافظه روی دیتابیس `:memory:`یِ بنچ‌مارک نوشته می‌شوند (نه
  دیتابیس اصلی بات)، ولی وب‌سرچ/فچ واقعی‌اند. تسک‌های تزریق عمداً محتوای
  مخرب دارند — دقیقاً برای اینکه ثابت شود بابی آن‌ها را به‌عنوان **داده**
  می‌بیند، نه دستور.
- توکن‌ها و کلیدها: رانر زنده از مسیر پیکربندی عادی (`AiGateway` روی
  دیتابیس دیپلوی) استفاده می‌کند؛ هیچ مقداری چاپ، لاگ یا کامیت نمی‌شود.

## غیراهداف (صریح)

- ❌ داوری کیفی با مدل زبانی (vibe-based judging) — همه‌چیز قطعی است.
- ❌ مقایسهٔ هزینه/توکن با هرمس — خروجی batch هرمس توکن نمی‌دهد.
- ❌ بنچ‌مارک فارسی عمومی — این سوئیت برای رفتار ایجنتی بابی طراحی شده،
  نه یک بنچ‌مارک زبانی جامع.
